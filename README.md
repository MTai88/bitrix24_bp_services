# Сервисы бизнес-процессов для Bitrix24

Модуль `mtai.bpservices` собирает универсальные списки (заявки, счета, документы)
в единую плитку **сервисов для сотрудников** на странице **`/bp-services/`**: иконка,
название, описание — и один клик до формы запуска нужного процесса.

Задача, которую решает модуль: сотрудник не должен помнить, в каком разделе меню
и какой список живёт («Счёт на оплату»? «Отпуск»?), и не должен видеть служебные
вкладки и кнопки интерфейса списков. Модуль даёт единую точку входа и настраивает
форму элемента списка «под сотрудника»: плоская форма полей, кнопки «Добавить/
Изменить», после сохранения — переход на «Запущенные процессы», где кнопка
«Запустить» скрыта — повторный запуск только со страницы сервисов.

Каталог сервисов — инфоблок **«Сервисы бизнес-процессов»**, каждый элемент —
карточка сервиса:

| Поле | Тип | Назначение |
|------|-----|------------|
| Название | поле элемента | отображается на плитке |
| Процесс (универсальный список) | свойство-селект `PROCESS_IBLOCK` | на какой список ссылается сервис |
| Иконка сервиса | свойство-файл `ICON` | картинка на плитке |
| Описание | `PREVIEW_TEXT` | подпись на плитке |

Варианты селекта «Процесс» заполняются **автоматически** из инфоблоков типа
`bitrix_processes` (универсальные списки) и поддерживаются в актуальном
состоянии обработчиками событий `OnAfterIBlockAdd / Update / Delete`.
XML_ID каждого варианта хранит ID инфоблока списка.

Инфоблок создаётся с **расширенным управлением правами** (`RIGHTS_MODE=E`):
по умолчанию администраторы — полный доступ, все пользователи — чтение;
дальше права настраиваются в админке (в т.ч. поэлементно). Плитка отдаёт
элементы с учётом этих прав — сотрудник не видит сервисы, к которым у него
нет доступа. При переустановке модуля уже настроенные права не перезаписываются.

## Публичная страница /bp-services/

Плитка сервисов для **авторизованных сотрудников**. Клик по карточке открывает
форму создания элемента привязанного списка, например для «Счёт на оплату»:

```
https://portal/bizproc/processes/13/element/0/0/?list_section_id=
```

Гости перенаправляются на `/auth/?backurl=/bp-services/`.

## Кастомизация формы элемента списка

Модуль доставляет копию компонента `bitrix:lists.element.edit` в
`local/components/bitrix/lists.element.edit/` (компонент скопирован целиком —
без `component.php` каталог в local ломает поиск компонента ядром). Изменения
шаблона `.default`:

- вкладка **«Раздел»** не выводится никому;
- вкладки **«Бизнес-процессы»** и **«Доступ»** и полоса вкладок — только
  администратору; сотрудник видит плоскую форму полей;
- кнопки: при создании — **«Добавить»**, при редактировании — **«Изменить»**,
  «Применить» убрана; **«Отменить»** ведёт на `/bp-services/` при добавлении
  и на `/bizproc/userprocesses/` при изменении;
- после сохранения: **добавление** возвращает на `/bizproc/userprocesses/`
  (ссылки плитки сервисов несут `back_url`), **изменение** остаётся на
  странице элемента с сохранёнными данными.

## Страница «Запущенные процессы»

Кнопка **«Запустить»** в тулбаре `/bizproc/userprocesses/` скрыта для всех —
единственная точка запуска процессов остаётся `/bp-services/`. Реализовано
обработчиком `OnEndBufferContent` модуля: на этой странице в `<head>`
добавляется `display:none` для кнопки (id строится из `GRID_ID` компонента
`bitrix:bizproc.user.processes`, сама кнопка рендерится клиентской частью).

Внимание: копия замораживает `component.php` — при обновлении модуля «Списки»
в Битрикс обновите копию из ядра, сохранив правки шаблона (помечены
комментариями `mtai.bpservices`).

## Загрузчик файлов FilePond (AJAX)

Поля-файлы формы списка (свойства типа «Файл») оформлены загрузчиком
[FilePond](https://pqina.nl/filepond/) (MIT): зона «перетащите файл или
выберите» с русскими подписями. Файл уходит на сервер **сразу при выборе**,
форма отправляет только его id — большое вложение не блокирует отправку
формы, прогресс виден в самом пруде.

Как устроено:

- **Контроллер модуля** `mtai:bpservices.file.upload` / `.revert`
  (`lib/controller/file.php`): проверяет авторизацию, sessid, что поле —
  свойство-файл этого инфоблока, размер (≤50 МБ) и расширения из настроек
  свойства; сохраняет файл в `CTempFile` (автоочистка агентами), мета —
  в сессии пользователя. `revert` (файл убрали из пруда) удаляет его сразу.
- **Форма** отправляет `mtai_bpservices_files[PROPERTY_X][nK] = id`;
  скрытые input'ы добавляются сразу по завершении загрузки и снимаются
  при удалении файла из пруда.
- **Мост в копии компонента** `lists.element.edit` перед сохранением
  восстанавливает файлы из id в `$_FILES` — дальше штатное сохранение
  свойств, валидация обязательности и БП не меняются. Владелец, инфоблок
  и свойство проверяются, чужие id не проходят.
- Множественные поля: **один пруд с мультизагрузкой на свойство** — ряды
  существующих файлов (превью, «Скачать», галочки «Удалить файл») остаются
  штатными, прячутся только слоты-замены и кнопка «Добавить». Скрытые слоты
  продолжают отправляться пустыми — именно на этих пустых записях `$_FILES`
  держится штатная механика «Удалить файл» (del применяется к отправленным
  слотам), поэтому input'ы не отключаются. Одиночное поле привязано к ключу
  слота значения: на добавлении это `n0` (новый файл), на редактировании —
  id значения (загрузка **заменяет** файл, как у нативного input). Без JS
  поля остаются нативными. Дистрибутив в модуле (`install/js/filepond/`),
  подключение инлайн — работает и в слайдере (`livefeed=y`). Удаление модуля
  убирает ассеты.

Что ставит установщик:

- инфоблок и свойства (описаны выше);
- обработчики событий синхронизации селекта;
- файл ` /bp-services/index.php` с компонентом `mtai:bpservices.grid`
  (кеширование с тегом инфоблока);
- файловый доступ на чтение для группы «Все пользователи» (гейт авторизации —
  в коде страницы).

Страница рендерится **в шаблоне портала по умолчанию**. Своего шаблона модуль
не ставит (до 0.4.1 ставился лёгкий `bp_services` — при обновлении он и его
правило в `b_site_template` автоматически удаляются).

Удаление модуля сносит всё перечисленное, включая элементы инфоблока.

## Установка

Скрин «Настройки → Модули → Сервисы бизнес-процессов → Установить», либо из
php-контейнера стенда:

```bash
docker exec bitrix24_test-php-1 php /var/www/html/local/tools/bpservices_install.php install
```

Требования: PHP 8.1+, модули `iblock` (обязателен) и `lists`/универсальные
списки (без них селект будет пустым до появления списков).

## Структура

```
admin/menu.php               пункт «Контент → Сервисы бизнес-процессов»
install/components/bitrix/lists.element.edit/  кастомная форма списка (в local/components)
install/components/mtai/bpservices.grid/       плитка сервисов (в local/components)
install/index.php            установщик
install/public/bp-services/  публичная страница (копируется в корень сайта)
lib/IblockManager.php        реестр: инфоблок, свойства, синхронизация селекта
lib/EventHandler.php         обработчики OnAfterIBlock* → синхронизация
```

API: `Mtai\Bpservices\IblockManager::getServicesIblockId()`,
`getProcessIblocks()`, `syncProcessEnum()`, `buildProcessFormUrl($id)`.
